## 第一、协程与线程

线程：操作系统层面的执行单元，由内核抢占式调度，拥有独立的栈空间和寄存器上下文。
协程：程序语言层面的执行单元，在 await 处主动暂停让出控制权，由事件循环在用户态调度。

调度权归属不同：线程是操作系统强制切换，你控制不了切在哪；协程只在 await 处主动让出，切换位置完全可控。
资源开销不同：线程占用 1~8MB 栈空间，创建销毁都是系统调用；协程只占约 1KB，本质就是个 Python 对象。
数据安全不同：多线程随时可能被切走，共享数据必须加锁；协程单线程执行，两个 await 之间的代码是原子的，天然线程安全。



## 第二、异步线程的定义与运行

async def 定义协程函数：调用只返回协程对象，不执行函数体。不 await 相当于计划书复印了一份但没人干活，程序结束时 Python 会报警告：coroutine was never awaited。
await 三件事：暂停当前协程 → 等待异步操作结果 → 把控制权交还给事件循环去跑别的任务。注意：await 只能在 async def 里用，普通函数写 await 直接语法报错。
asyncio.run() 是入口：创建事件循环 → 把协程丢进去执行 → 结束后关闭循环。整个程序只调用一次，不能嵌套，不能在已有事件循环里再调用（比如 FastAPI 路由里不行）。



## 第三、关键规则

同步函数不能直接调用异步函数（需用asyncio.run()）；

```python
async def fetch():
    return "data"

def sync_func():
    result = fetch()  # ❌ 只拿到协程对象，没执行
    # 正确：result = asyncio.run(fetch())
```

异步函数内不能用同步阻塞代码（如time.sleep()）；

```python
async def bad():
    time.sleep(5)  # ❌ 整个事件循环卡死，所有协程跟着等
    # 正确：await asyncio.sleep(5)
```

await才会真正执行协程，否则只是创建了未运行的对象；

```python
async def task():
    return "done"

coro = task()         # 创建协程对象，什么都没发生
result = await coro   # 真正执行，拿到结果
```

await关键字只能在async def定义的函数内使用，普通函数中语法报错。

```python
def normal():
    await something()  # ❌ SyntaxError
    
    
async def main():
    asyncio.run(inner())  # ❌ 事件循环里不能再套事件循环
```

## 第四、gather 并发执行

asyncio.gather()是并发核心，同时启动多个任务并行等待。三个各需1秒的任务，顺序执行需3秒，用gather并发只需1秒（取最慢那个）。原理是遇到IO就切换，多个任务的等待时间重叠，总耗时等于最慢单个耗时而非累加。关键参数return_exceptions=True让某个任务异常时不中断其他任务，异常以对象形式放在结果列表中，后续可统一处理而不丢失正常结果。

```python
async def download(name, seconds):
    await asyncio.sleep(seconds)
    return f"{name} 完成"

async def main():
    # 顺序执行：1+2+3 = 6秒
    # await download("A", 1)
    # await download("B", 2)
    # await download("C", 3)

    # 并发执行：max(1,2,3) = 3秒
    results = await asyncio.gather(
        download("A", 1),
        download("B", 2),
        download("C", 3)
    )
```

```python
async def might_fail(i):
    await asyncio.sleep(1)
    if i == 2:
        raise ValueError(f"任务{i}失败")
    return f"任务{i}成功"
#一个抛异常，gather 立即抛，其他任务可能被取消。加上 return_exceptions=True，异常当作返回值放在结果列表对应位置，后续统一处理。
results = await asyncio.gather(
    might_fail(1),
    might_fail(2),
    might_fail(3),
    return_exceptions=True
)
# results: ['任务1成功', ValueError('任务2失败'), '任务3成功']
```

```python
# as_completed：谁先回来先处理谁
for coro in asyncio.as_completed([task1, task2, task3]):
    result = await coro  # 先完成的先拿到
    print(result)
```

**gather vs create_task 选择**

| 场景                     | 用法                                     |
| :----------------------- | :--------------------------------------- |
| 等所有任务一起完成       | `await gather(*tasks)`                   |
| 某个失败不连累其他       | `gather(*tasks, return_exceptions=True)` |
| 只需要"发出去"，不等结果 | `create_task()`                          |
| 先完成先处理，不等慢的   | 用 `as_completed()` 不用 `gather`        |

## 第五、后台任务

asyncio.create_task()将协程包装成Task提交给事件循环立即调度执行，不阻塞当前代码继续运行。适合发通知、写日志等不需要立即结果的场景。返回的Task对象可在后续await获取结果。注意必须保存Task引用防止被垃圾回收，用gather统一等待更稳妥。

```python
#适用场景 发通知、写日志、预热缓存、异步上报监控数据——凡是不需要立即拿到结果、失败了也能接受的附加操作。
async def send_notification(user):
    await asyncio.sleep(2)
    print(f"通知已发送给 {user}")

async def handle_request():
    # 创建后台任务，立即返回，不等待
    task = asyncio.create_task(send_notification("张三"))

    # 主逻辑继续执行，不受影响
    print("处理请求...")
    await asyncio.sleep(0.5)
    print("请求处理完成")

    # 最后确保后台任务完成
    await task
```

## 第六、超时与取消

asyncio.wait_for(协程, 秒数)给异步操作加超时，超时抛出TimeoutError，可捕获做降级处理。task.cancel()向任务发送取消信号，被取消方在await处抛出CancelledError，应捕获做清理工作。两者组合实现可靠的外调保护，避免资源泄露和无限等待。

```python
# 超时后内部自动调用了 task.cancel()，向目标协程发出取消信号。
async def external_api_call():
    await asyncio.sleep(10)
    return "done"

async def main():
    try:
        result = await asyncio.wait_for(external_api_call(), timeout=3)
    except asyncio.TimeoutError:
        print("调用超时，使用降级数据")
        result = fallback_data()
```

```python
# 取消只在 await 处生效，纯计算循环（无 await）无法被取消
# 捕获 CancelledError 做清理后必须重新 raise，否则取消被吞掉
task = asyncio.create_task(long_running_job())
await asyncio.sleep(1)
task.cancel()  # 向 task 的当前 await 处抛出 CancelledError

try:
    await task
except asyncio.CancelledError:
    print("任务已取消，执行清理")
    
async def cancellable_task():
    try:
        while True:
            await asyncio.sleep(1)  # 在这里被取消
            do_work()
    except asyncio.CancelledError:
        cleanup_resources()
        raise  # 必须重新抛出，不然外部不知道被取消了
```

```python
# wait_for 超时后的残留问题   不 await 被取消的 task，可能留下未清理的资源。
try:
    result = await asyncio.wait_for(task, timeout=3)
except asyncio.TimeoutError:
    # task 已被 cancel，但最好显式 await 确认清理完成
    try:
        await task
    except asyncio.CancelledError:
        print("已确认任务完全取消")
```

```python
# gather 本身没有 timeout 参数，配合 wait_for 使用
try:
    results = await asyncio.wait_for(
        asyncio.gather(task1, task2, task3),
        timeout=10
    )
except asyncio.TimeoutError:
    print("批量任务整体超时")
```

## 第七、并发控制（限流）

asyncio.Semaphore(n)信号量限制同时执行的任务数为n，超出部分自动排队等待，保护下游服务不被冲垮。asyncio.Queue实现生产者消费者模式，多个生产者放入任务，多个消费者取出处理，join()阻塞直到队列所有任务处理完毕，适合流水线场景。

```python
#async with sem 进入时计数器减1，计数器为0则阻塞等待；退出时计数器加1，唤醒下一个排队者。保护下游服务不被瞬时流量冲垮。
async def fetch_with_limit(sem, url):
    async with sem:              # 获取信号量，超出限制则在此排队
        await asyncio.sleep(1)   # 模拟请求
        return f"{url} done"

async def main():
    sem = asyncio.Semaphore(5)   # 最多同时5个
    tasks = [fetch_with_limit(sem, f"url_{i}") for i in range(100)]
    results = await asyncio.gather(*tasks)
    # 100个请求，但同一时刻最多只有5个在执行
```

```python
# 生产者放入任务，消费者取出处理，队列解耦双方速度差异。maxsize 限制缓冲区大小防止内存暴涨，join() 等待队列清空，task_done() 配合 join() 使用。
async def producer(queue):
    for i in range(20):
        await queue.put(f"任务{i}")
        await asyncio.sleep(0.1)   # 生产间隔

async def consumer(queue, worker_id):
    while True:
        task = await queue.get()
        print(f"消费者{worker_id} 处理 {task}")
        await asyncio.sleep(0.5)   # 处理耗时
        queue.task_done()          # 标记任务完成

async def main():
    queue = asyncio.Queue(maxsize=10)      # 队列容量限制，满了生产者阻塞
    workers = [asyncio.create_task(consumer(queue, i)) for i in range(3)]
    await producer(queue)
    await queue.join()                     # 等队列中所有任务处理完毕

    for w in workers:                      # 停止消费者
        w.cancel()
```

**Semaphore vs Queue 选择**

| 场景                       | 工具                  |
| :------------------------- | :-------------------- |
| 一批任务并发执行但要限流   | `Semaphore`           |
| 生产消费速度不匹配，需缓冲 | `Queue`               |
| 多个消费者竞争同一批任务   | `Queue`               |
| 两者组合：限流 + 缓冲      | `Semaphore` + `Queue` |

```python
# 简单限流：控制启动间隔
for i in range(100):
    await asyncio.sleep(0.1)   # 每0.1秒发一个
    task = asyncio.create_task(fetch(i))

# 分批执行：每批等完再发下一批
batch_size = 10
for i in range(0, 100, batch_size):
    batch = tasks[i:i+batch_size]
    await asyncio.gather(*batch)
    await asyncio.sleep(0.5)   # 批次间隔
```
