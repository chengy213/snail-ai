## 项目概述

这是一个基于 **FastAPI** 框架构建的 **用户管理 CRUD 示例项目**，属于"Python学习之项目实战"系列。项目采用前后端分离但同仓部署的方式，后端提供 RESTful API，前端是一个纯 HTML/CSS/JS 单页面应用（SPA），通过静态文件服务挂载。

- **技术栈**：Python 3.13 + FastAPI + SQLAlchemy 2.0 + MySQL (PyMySQL) + Pydantic V2 + Loguru
- **前端**：原生 HTML/CSS/JS（无框架），响应式布局
- **数据库**：MySQL，通过 SQLAlchemy ORM 自动建表
- **项目名称**：User Manage v1.0.0

## 各文件详细分析

### 1. `app/main.py` — 应用主入口

是整个应用的启动入口和中心组装点，负责：

- **生命周期管理**：通过 `lifespan` 异步上下文管理器，在应用启动时自动调用 `init_db()` 创建数据库表（基于 SQLAlchemy ORM 模型），启动后验证表是否成功创建。
- **FastAPI 实例化**：创建 `FastAPI` 实例，配置标题、版本、Swagger/ReDoc 文档路径。
- **中间件注册**：注册 CORS 中间件，允许跨域请求（开发阶段允许所有来源）。
- **全局异常处理器**（4 层异常捕获）：
  - `AppBaseException` — 业务自定义异常，返回对应的 HTTP 状态码
  - `RequestValidationError` — Pydantic 请求参数校验失败，返回 422
  - `SQLAlchemyError` — 数据库操作异常，返回 500
  - `Exception` — 兜底全局异常，返回 500
- **路由注册**：挂载 `/api/v1` 前缀的用户路由，挂载 `/static` 静态文件目录。
- **健康检查**：`GET /` 返回应用基本信息，`GET /health` 返回健康状态。
- **开发服务器**：`__main__` 中使用 uvicorn 启动，支持 `--reload` 热重载。

### 2. `app/core/config.py` — 配置管理

使用 **Pydantic Settings** 实现类型安全的配置管理：

- 定义了 `Settings` 类，字段包括：`APP_NAME`、`APP_VERSION`、`DEBUG`、以及数据库连接参数（`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`）。
- `database_url` 属性：动态拼接 MySQL 连接字符串（`mysql+pymysql://...`），使用 utf8mb4 字符集。
- 通过 `model_config` 指定 `.env` 文件路径（项目根目录），区分大小写。
- 全局单例 `settings = Settings()` 供所有模块使用。

### 3. `app/core/database.py` — 数据库连接管理

基于 **SQLAlchemy 2.0** 风格管理数据库连接：

- **引擎创建**：使用 `create_engine` 创建 MySQL 引擎，配置连接池（`QueuePool`，池大小 10，最大溢出 20），开启 `pool_pre_ping` 检测连接有效性，连接回收时间 3600 秒。
- **会话工厂**：`SessionLocal` 使用 `sessionmaker`，关闭自动提交和自动刷新，由业务层手动控制事务。
- **声明式基类**：`Base = declarative_base()`，所有 ORM 模型继承此类。
- **依赖注入函数** `get_db()`：生成器函数，为每个请求创建数据库会话，请求结束后自动关闭，通过 FastAPI 的 `Depends` 注入到路由中。

### 4. `app/core/exceptions.py` — 自定义异常体系

定义了分层级的业务异常类，全部继承自 `AppBaseException`：

| 异常类                       | HTTP 状态码 | 用途                                      |
| ---------------------------- | ----------- | ----------------------------------------- |
| `AppBaseException`           | 400         | 基础异常，包含 message、status_code、data |
| `ResourceNotFoundException`  | 404         | 资源不存在（如用户未找到）                |
| `DuplicateResourceException` | 409         | 资源重复冲突（如账号/邮箱已存在）         |
| `ValidationException`        | 422         | 业务层数据验证失败                        |
| `DatabaseException`          | 500         | 数据库操作失败                            |
| `AuthenticationException`    | 401         | 认证失败（预留，当前未使用）              |

这些异常在 `main.py` 中被全局异常处理器统一捕获，转换为标准 JSON 响应。

### 5. `app/core/logger.py` — 日志系统

使用 **Loguru** 库替代 Python 标准 logging，配置了三路输出：

- **控制台输出**（stderr）：DEBUG 级别，带颜色，格式为 `时间 | 级别 | 消息`。
- **常规日志文件**：INFO 级别，按日切割（`logs/app_YYYY-MM-DD.log`），10MB 自动切割，保留 30 天，旧日志 zip 压缩。格式包含时间、级别、位置（文件:函数:行号）、消息、request_id。
- **错误日志文件**：ERROR 级别，按日切割（`logs/error_YYYY-MM-DD.log`），保留 90 天，格式包含完整异常堆栈。

### 6. `app/models/user.py` — 用户 ORM 模型

使用 SQLAlchemy ORM 定义 `sys_user` 表结构：

| 字段            | 类型        | 约束                 | 说明                 |
| --------------- | ----------- | -------------------- | -------------------- |
| `id`            | Integer     | 主键，自增           | 用户唯一标识         |
| `username`      | String(50)  | 唯一索引，非空       | 登录账号             |
| `password`      | String(255) | 非空                 | 哈希存储的密码       |
| `real_name`     | String(50)  | 非空                 | 真实姓名             |
| `gender`        | Enum        | 默认"未知"           | 性别（男/女/未知）   |
| `email`         | String(100) | 唯一索引，可选       | 电子邮箱             |
| `phone`         | String(20)  | 唯一索引，可选       | 电话号码             |
| `is_active`     | Boolean     | 默认 True            | 是否激活             |
| `remark`        | Text        | 可选                 | 备注                 |
| `created_at`    | DateTime    | server_default=now() | 创建时间             |
| `updated_at`    | DateTime    | onupdate=now()       | 更新时间（自动更新） |
| `last_login_at` | DateTime    | 可选                 | 最后登录时间         |

- 定义了 `GenderEnum` 枚举类（男/女/未知），使用 `SQLEnum` 映射到数据库。
- `__repr__` 方法用于调试输出。

### 7. `app/schemas/user.py` — 数据校验模式

使用 **Pydantic V2** 定义请求和响应的数据结构：

**请求模式**：

- `UserCreateRequest`：创建用户字段校验，包含 `username`（3-50字符，纯字母数字下划线）、`password`（6-50字符）、`real_name`、`gender`、`email`（EmailStr 格式）、`phone`（11位手机号正则校验）等，使用 `@field_validator` 装饰器做自定义校验。
- `UserUpdateRequest`：更新用户字段（全部可选），使用 `exclude_unset=True` 实现部分更新。同样有 phone 和 gender 的校验。
- `UserQueryRequest`：分页查询参数，`page`（≥1）、`page_size`（1-100），以及多个模糊查询字段。

**响应模式**：

- `UserResponse`：返回给客户端的用户数据，**不含密码**，启用 `from_attributes=True` 支持从 ORM 对象自动转换。
- `UserListResponse`：分页列表响应，包含 `items`、`total`、`page`、`page_size`。

### 8. `app/services/user.py` — 业务逻辑层（UserService）

封装所有用户业务逻辑，是一个纯静态方法的服务类：

- **密码安全**：使用 SHA-256 + 随机盐值（`secrets.token_hex(16)`）进行密码哈希，格式为 `salt$hash`。验证时使用 `secrets.compare_digest` 做时间恒定比较防止时序攻击。注意：`requirements.txt` 中的 `passlib` 和 `bcrypt` 已被注释/弃用，改用内置库实现。
- **唯一性检查** `_check_unique_fields()`：检查 `username`、`email`、`phone` 是否已存在，支持排除指定 ID（更新时排除自身）。
- **CRUD 方法**：
  - `create_user()`：唯一性检查 → 创建 ORM 对象 → `db.add()` → `db.commit()` → `db.refresh()`，异常时 `db.rollback()`。
  - `get_user_by_id()`：按 ID 查询，不存在时抛 `ResourceNotFoundException`。
  - `get_user_list()`：支持多条件模糊查询 + 分页，按创建时间倒序排序，返回 `UserListResponse`（含 total 总数）。
  - `update_user()`：查找用户 → 唯一性检查（排除自身）→ `model_dump(exclude_unset=True)` 只更新已设置字段 → 提交。
  - `delete_user()`：查找用户 → `db.delete()` → 提交。
  - `update_last_login()`：更新最后登录时间（预留功能，当前未在 API 层调用）。
- 所有方法都有完整的异常处理：业务异常（`ResourceNotFoundException`、`DuplicateResourceException`）直接向上抛出，系统异常包装为 `DatabaseException`。

### 9. `app/api/v1/user.py` — API 路由层

定义 RESTful 用户管理接口，路由前缀 `/users`，完整路径 `/api/v1/users`：

| 方法     | 路径                  | 功能                          |
| -------- | --------------------- | ----------------------------- |
| `POST`   | `/`                   | 创建用户                      |
| `GET`    | `/{user_id}`          | 获取用户详情                  |
| `GET`    | `/`                   | 获取用户列表（分页+条件查询） |
| `PUT`    | `/{user_id}`          | 更新用户信息（部分更新）      |
| `DELETE` | `/{user_id}`          | 删除用户                      |
| `PUT`    | `/{user_id}/activate` | 切换用户激活/停用状态         |

- 使用 FastAPI 的 `Depends(get_db)` 实现数据库会话的依赖注入。
- 使用 `Path` 和 `Query` 做参数描述和校验。
- 所有接口返回统一格式 `{code, message, data}` 字典。
- 路由层只负责参数接收和响应封装，具体逻辑委托给 `UserService`。

### 10. `app/utils/response.py` — 统一响应格式

定义了标准 API 响应结构：

- `ResponseModel`：泛型响应模型，结构 `{code: 200, message: "操作成功", data: T}`。
- `PaginatedResponse`：分页响应模型。
- `success_response(data, message)`：快捷函数，返回 `{code: 200, message, data}`。
- `error_response(code, message, data)`：快捷函数，返回 `{code, message, data}`。

确保所有 API 接口返回格式一致，便于前端统一处理。

### 11. `static/index.html` — 前端管理页面

一个完整的单页面用户管理界面，特点：

- **纯原生实现**：无任何前端框架依赖，使用 HTML5 + CSS3 + ES6 JavaScript。
- **响应式设计**：使用 CSS Grid 和媒体查询，支持 PC 和移动端。
- **CSS 变量系统**：统一的颜色、圆角、阴影等设计 Token。
- **功能模块**：
  - **系统信息头部**：显示应用名称、版本，实时健康检查指示器。
  - **统计卡片**（4个）：用户总数、活跃用户、停用用户、性别分布。
  - **搜索工具栏**：支持按用户名、真实姓名、邮箱、手机号、性别、状态组合搜索。
  - **用户数据表格**：展示所有字段，包含性别/状态彩色标签，操作按钮（编辑/启停/删除）。
  - **分页组件**：页码导航，显示总记录数和当前范围。
  - **模态弹窗**：新建/编辑用户表单（字段校验 + 前端校验），删除确认弹窗。
  - **Toast 消息提示**：右上角滑入动画，支持 success/error/warning 类型。
  - **键盘快捷键**：ESC 关闭弹窗。
- **API 通信**：自动检测运行环境，封装 `apiRequest()` 函数统一处理请求和错误。
- **安全措施**：`escapeHtml()` 防 XSS。

## 架构设计

```
请求 → API路由层 (api/v1/user.py)
       → 依赖注入 get_db() 获取数据库会话
       → 委托业务逻辑层 (services/user.py)
         → ORM模型层 (models/user.py) 操作数据库
         → Schema层 (schemas/user.py) 校验数据
       → 返回统一响应格式 (utils/response.py)
       
异常 → 全局异常处理器 (main.py) → 统一错误响应
```

项目遵循**分层架构**原则：

1. **路由层** — 只处理 HTTP 参数和响应封装
2. **业务逻辑层** — 核心业务规则和流程
3. **数据访问层** — ORM 模型和数据库操作
4. **基础设施层** — 配置、日志、异常、响应工具

## 技术要点

- **密码安全**：SHA-256 + 随机盐值，使用 `secrets.compare_digest` 防时序攻击
- **事务管理**：业务异常和系统异常均执行 `db.rollback()`，保证数据一致性
- **部分更新**：`model_dump(exclude_unset=True)` 只更新客户端明确提供的字段
- **全局异常处理**：四层异常捕获（业务异常 → 参数校验异常 → 数据库异常 → 兜底异常）
- **数据库自动建表**：应用启动时通过 `Base.metadata.create_all()` 自动创建表
- **连接池管理**：QueuePool（10+20），连接预检和定时回收
- **日志分级**：DEBUG（控制台）/ INFO（常规文件）/ ERROR（错误文件），按大小切割，按天保留
