## 1、什么是大模型？

大语言模型（LLM）是当代人工智能应用的核心推理引擎，充当应用的“认知中枢”，负责语义理解、逻辑推理与内容生成。以下为主流基础模型及其技术特征：

**GPT 系列 (OpenAI)**
标杆级通用模型，在文本理解与生成方面位居前列。原生支持多模态图像识别，拥有完善的工具调用生态，包括函数调用、代码解释器等高级功能。

**Claude 系列 (Anthropic)**
以超长上下文窗口（200K tokens）著称，擅长大规模文档的深度分析。输出风格严谨审慎，在复杂逻辑推理与代码生成领域表现卓越，安全性机制设计为其核心差异化优势。

**Gemini 系列 (Google)**
业界领先的原生多模态模型，可无缝融合文本、图像、音频及视频等多种模态信息。百万级 token 上下文窗口为长序列建模提供可能，与谷歌云服务及生态体系深度集成。

**通义千问 (阿里云)**
中文语义理解能力突出，提供从轻量级 0.5B 到超大规模 110B 的完整参数谱系，全面满足端侧部署到云端推理的多样化需求，支持企业商用授权。

**DeepSeek (深度求索)**
国产开源模型的性能标杆，在代码生成与数学推理等逻辑密集型任务上表现突出，以显著的成本优势实现接近顶级闭源模型的性能水平。

| 模型        | 所属厂商  | 核心优势     | 特色能力                            | 适用场景                         |
| ----------- | --------- | ------------ | ----------------------------------- | -------------------------------- |
| GPT 系列    | OpenAI    | 综合能力顶尖 | 多模态识别、函数调用、代码解析      | 通用创作、智能交互、工具开发     |
| Claude 系列 | Anthropic | 超长上下文   | 200K 上下文、高安全机制、强逻辑推理 | 长篇文档分析、合规文案、复杂运算 |

| 通义千问    | 阿里云    | 中文适配优秀 | 全参数梯度版本、企业商用授权        | 国内办公、本地化业务部署         |

## 2、大模型API调用过程？

API调用本质是向云端推理服务发起一个符合规范的 HTTPS 请求，将模型推理这一计算密集型任务完全卸载到服务商侧。核心流程抽象为四步：
1、鉴权：通过 API Key 或 OAuth 2.0 进行身份认证
2、请求构建：按照模型要求的 Schema 组织 JSON 载荷，包含消息列表、生成参数等
3、同步/异步调用：等待完整响应返回，或通过流式传输逐步获取 token
4、响应解析：从返回的结构化数据中提取生成文本及 token 用量元数据

## 3、什么是Prompt 工程？

​		Prompt工程（提示词工程）是一种以自然语言为媒介的编程范式，通过系统化设计与优化输入给大模型的指令文本，在不修改模型参数的前提下精确引导其行为与输出质量。

其核心组成包括：定义模型身份与边界的系统指令、明确具体目标的任务描述、规范输出形式的格式约束，以及可选的示例示范与推理路径引导。

它的关键特点是零成本适配——无需微调即可快速切换任务；高度可控——通过结构化约束确保输出稳定可解析；可版本管理——将Prompt视为代码资产进行迭代与评测，从而在大模型应用开发栈中承担起“以文控智”的枢纽角色。

## 4、什么是向量数据库？

​		向量数据库是一种专为存储、索引和检索高维向量数据而设计的数据库系统，其核心是以非结构化数据经 Embedding 模型转化后的数值向量为处理对象，通过余弦相似度或欧氏距离等度量进行相似性搜索，并依赖 HNSW、IVF 等近似最近邻（ANN）索引算法实现海量数据下的快速检索。
​		它的核心价值在于，解决了传统数据库难以处理的语义理解问题，作为“记忆中枢”为大模型提供可依赖的外部知识，是 RAG（检索增强生成）等 AI 应用的关键基础设施。
​		当前主流开源的有：分布式标杆 Milvus、轻量友好的 Chroma、支持 GraphQL 与知识图谱的 Weaviate、算法库 Faiss 以及可作为插件集成的关系型数据库扩展（如 pgvector）。
​		技术原理上，向量数据库首先将文本、图像等非结构化数据通过深度学习模型（如 Transformer）映射为高维空间中的坐标点。检索时，利用 HNSW 等图索引算法进行快速导航，能在毫秒内找到最接近的“邻居”，实现从“精确匹配”到“模糊联想”的跨越。

## 5、什么是嵌入模型（Embedding Model）？

嵌入模型是一种将文本、图像等非结构化数据映射为连续、低维、稠密数值向量的神经网络模型，核心价值在于让语义相近的内容在向量空间中距离也相近，从而实现机器对语义的理解而非关键词匹配。

其主要作用是作为大模型与外部知识库之间的桥梁，支撑语义搜索、检索增强生成（RAG）、多模态对齐等关键场景。

开源主流模型方面，中文场景优选 bge-large-zh-v1.5，多语言场景可选用 bge-m3，追求极致性能可考虑 gte-Qwen2-7B-instruct，而 m3e 和 text2vec 则是中文社区的性价比之选。

技术原理上，它基于Transformer架构，通过分词、多层编码和向量汇聚（如平均池化），并采用对比学习等策略训练而成。其优点在于语义理解深刻、可多模态扩展并赋能下游任务；缺点则是性能高度依赖训练数据质量，对细微语义差别（如否定词）可能不敏感，
且推理过程需消耗一定计算资源，可解释性也相对较弱。

## 6、什么是文本分割器？

​		文本分割器是RAG流程中的关键预处理组件，负责将长篇文档拆解为多个长度适中、语义相对独立的文本块，核心目标是在信息完整性与检索精准度之间取得最佳平衡。其基本作用是将大模型无法一次性处理的长文档切割为可“消化”的片段，切割质量直接影响后续检索与生成效果——块过大则信息混杂、噪音增多，块过小则完整语义被拆散、关键信息丢失。

主流开源方案中，LangChain的RecursiveCharacterTextSplitter通过按段落、换行、句号等分隔符递归切分，是最通用的首选；LlamaIndex的SentenceSplitter基于句子边界切分，适合精细问答；MarkdownHeaderTextSplitter和HTMLHeaderTextSplitter分别依据Markdown和HTML标题层级进行结构化切分；TokenTextSplitter按模型Token数精准度量，适合严格控制成本的场景；Semantic Chunker则通过计算句子间语义相似度进行切分，语义连贯性最佳。技术原理上，分割器按照预设策略遍历文档，在满足chunk_size上限的前提下，优先在分隔符处断开以保持语义完整，并通过chunk_overlap保留相邻块间的重叠内容，防止关键信息恰好落在边界上被切断。

其优点是策略灵活可组合、实现轻量高效、能显著提升检索精度；缺点是分割效果高度依赖参数调优，固定规则切分难以适配所有文档类型，语义切分虽效果好但计算成本高、速度慢。

| ------------------------------ | -------------------------------- | ------------------------ | ----------------------------- |
| RecursiveCharacterTextSplitter | 递归按换行、标点、段落逐层切割   | 通用性强，均衡长度与语义 | 通用文档常规分割              |
| SentenceSplitter               | 依照句子边界精细拆分             | 语句完整性高，粒度细腻   | 精细化问答检索                |
| MarkdownHeaderTextSplitter     | 依托 Markdown 标题层级结构化切分 | 保留文档层级逻辑         | 笔记、技术文档、markdown 文件 |
| HTMLHeaderTextSplitter         | 根据 HTML 标签标题结构切割       | 贴合网页排版架构         | 网页抓取内容解析              |

| Semantic Chunker               | 计算语义相似度划分区块           | 语义连贯性最优           | 专业文稿、高精度知识库检索    |

## 7、LangChain是什么？

LangChain 是一个专为大语言模型应用开发设计的开源框架，旨在将 LLM 与外部工具、数据源和记忆机制串联起来，构建复杂、可扩展的智能应用。

其核心作用在于，通过标准化的接口和可组合的组件，将原本孤立的大模型能力（推理）与外部资源（搜索、数据库、API）无缝集成，从而解决了大模型无法访问私有知识、缺乏长期记忆和无法执行具体操作的根本局限。它提供了模型包装、提示词管理、对话记忆、文本分割、向量数据库集成及智能代理等一系列积木式模块。技术原理上，它采用“链（Chain）”作为核心抽象，允许开发者将多个功能单元按顺序或条件串接成一个端到端的处理流水线，实现从用户提问到获得最终答案的全流程自动化。

其优点是开发效率极高、模块高度解耦且生态丰富，是目前 RAG 和 Agent 应用开发的事实标准；缺点则是过度抽象使得底层实现不易调试，版本迭代快导致 API 频繁变动，且在高并发或极简场景下显得较为臃肿。

## 8、LangGraph是什么？

LangGraph是一个基于图结构的大模型应用编排框架，通过将应用程序建模为由节点（功能单元）和边（执行路径）组成的有向图，突破了传统线性链式流程的局限。

其核心作用是构建复杂的、有状态的Agent系统与多步骤工作流，原生支持循环、条件分支和人工干预等非线性控制逻辑，解决了LangChain链式结构在处理多轮对话、多智能体协作等场景时状态管理困难、逻辑耦合度高的问题。

技术原理上，LangGraph采用状态机（StateGraph）作为核心抽象，将业务逻辑封装为节点，通过条件边实现动态路由，并维护一个贯穿始终的中央状态对象，
确保在复杂流程中数据的可靠传递与持久化。

其优点在于能清晰表达复杂控制流、实现精细的状态管理和错误重试、天然支持多智能体协作与可视化调试；缺点则是技术门槛较高，开发者需理解图编排与状态机概念，且它主要面向Agent系统，简单线性任务使用LangGraph反而会增加不必要的开发复杂度。

## 9、LlamaIndex是什么？

LlamaIndex是一个专为RAG（检索增强生成）场景设计的数据框架，其核心定位是充当大模型与私有外部数据之间的“智能桥梁”。

它的主要作用是解决大模型无法访问私有知识、存在“幻觉”等根本局限，通过高效的数据摄取、索引和检索，将企业内部的非结构化数据（如PDF、文档、数据库）与LLM无缝连接。

其技术原理基于四层架构：通过数据连接器接入多源异构数据并标准化为Document对象；由Node解析器将文档切分为适合检索的最小语义单元；利用索引引擎将Node向量化并构建混合索引（如向量+关键词）；最终由查询引擎或智能体根据语义相似度检索相关上下文，并协同LLM生成精准答案。

它的优点是高度聚焦于RAG场景、上手极快、数据接入能力强大（支持160+种数据源），能在较短时间内构建出高质量的知识库问答系统；缺点则是通用性不如LangChain，在构建复杂的自定义工作流或高灵活性的Agent系统时显得能力受限。

## 10、LangSmith是什么？

LangSmith 是一个专为生产级大语言模型（LLM）应用打造的全生命周期管理平台，充当从原型开发到线上运维的桥梁。

其核心作用是解决 LLM 应用开发中调试困难、缺乏评估和运维复杂的问题，让开发者能够清晰地“看见”并优化模型内部的工作流程。

它提供全链路追踪，通过“追踪树”可视化应用每一步的执行逻辑、耗时与 Token 消耗，让黑箱变透明。在评估方面，它支持自动化测试并利用“LLM 裁判”等方式量化模型输出质量。部署上线后，它能实时监控应用的响应时间、错误率、成本等关键指标。

其优点在于为 LLM 应用开发提供了一体化、标准化的 DevOps 工具链，极大提升了开发效率和系统稳定性；缺点则是学习门槛较高，且与 LangChain 生态深度绑定，对新手和非 LangChain 用户不太友好。
